## Common Development Commands

**Backend (Laravel PHP)**
- `composer install` – install PHP dependencies.
- `php artisan migrate` – run database migrations.
- `php artisan serve` – start the local development server (http://127.0.0.1:8000).
- `php artisan test` – run the Laravel test suite.
- `composer lint` – runs Pint code style linter (see `composer.json` scripts).
- `php artisan config:clear` – clear cached configuration (useful before tests).

**Frontend (React + Vite)**
- `npm install` – install Node.js dependencies.
- `npm run dev` – start Vite with hot‑module reloading; works with the PHP server.
- `npm run build` – produce a production bundle in `public/build/`.
- `npm run lint` – run ESLint with auto‑fix.
- `npm run lint:check` – lint without modifying files.
- `npm run format` – format code with Prettier.
- `npm run format:check` – verify formatting.
- `npm run types:check` – run `tsc --noEmit` to validate TypeScript types.

**Combined development (via Composer)**
- `composer dev` – concurrently runs `php artisan serve`, `php artisan queue:listen`, and `npm run dev` (see the `dev` script in `composer.json`).

**Running a single test**
- `php artisan test --filter=ClassName` – run tests matching a specific PHPUnit/Pest class.
- `php artisan test --filter=methodName` – run a single test method.

**Utility**
- `php artisan key:generate` – generate the application key (run after cloning).
- `php artisan route:list` – list all registered HTTP routes.
- `php artisan storage:link` – expose the `storage/app/public` directory.

## High‑Level Architecture Overview

### Backend (Laravel)
- **Entry point**: `public/index.php` boots the framework.
- **Routing**: All web routes are defined in `routes/web.php`. Routes are grouped by role (`admin`, `receptionist`, `doctor`, `lab_technician`, `accountant`, `patient`) and protected by the `role` middleware.
- **Controllers**: Located under `app/Http/Controllers/`. Each role has its own namespace (e.g., `App\Http\Controllers\Doctor\AppointmentController`). Controllers handle validation, invoke model logic, and return Inertia responses.
- **Models**: In `app/Models/`. Core entities include `User`, `StaffProfile`, `DoctorProfile`, `PatientProfile`, `Appointment`, `Prescription`, `AnalysisRequest`, `BillingRecord`, etc.
- **Middleware**: `CheckRole.php` enforces role‑based access; `HandleInertiaRequests.php` prepares shared Inertia data.
- **Authentication**: Provided by Laravel Fortify (see `app/Providers/FortifyServiceProvider.php`). Supports registration, email verification, password resets, and 2‑FA.
- **Configuration**: Standard Laravel config files under `config/`. Environment variables are loaded from `.env` (generated from `.env.example`).

### Frontend (React + Inertia + Vite)
- **Entry point**: `resources/js/app.tsx` creates the Inertia app, selects the correct layout (AppLayout, AuthLayout, SettingsLayout) based on the page name, and initializes the UI theme.
- **Pages**: Under `resources/js/pages/`. Each page corresponds to a Laravel route (e.g., `pages/doctor/appointments/create.tsx`). Pages are React components exported as default.
- **Layouts**: Shared wrappers in `resources/js/layouts/` – `app-layout.tsx` (main shell), `auth-layout.tsx` (full‑screen auth pages), and `settings/layout.tsx` (settings section).
- **UI Components**: Reusable components in `resources/js/components/` and `resources/js/components/ui/`. Built on Radix UI primitives and Tailwind‑styled classes.
- **Hooks**: Custom hooks in `resources/js/hooks/` provide utilities such as theme handling (`use-appearance.tsx`), clipboard access, flash toasts, and role‑specific logic.
- **Styling**: Tailwind CSS compiled by Vite. `tailwind-merge` is used to combine class lists. Prettier and ESLint enforce consistent style.
- **TypeScript**: Types are defined in `resources/js/types/`. Run `npm run types:check` to validate.

### Build & Asset Pipeline
- **Vite**: Configured via `vite.config.ts` (generated by `@laravel/vite-plugin`). Handles HMR during `npm run dev` and produces optimized bundles on `npm run build`.
- **Inertia**: Bridges Laravel routes to React components without a separate API layer; data is passed via Inertia props.

### Testing Strategy
- **PHP**: `php artisan test` runs the Laravel test suite (uses Pest under the hood). Tests are located in `tests/`.
- **JS/TS**: No dedicated test runner, but linting (`npm run lint`) and type checking (`npm run types:check`) are part of CI (`composer ci:check`).
